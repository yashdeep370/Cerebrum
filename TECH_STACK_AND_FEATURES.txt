===================================================================
CEREBRUM — AI-Powered Document Intelligence Platform
===================================================================

WHAT IT DOES
-------------------------------------------------------------------
Cerebrum lets you upload documents and immediately get value out of
them without reading them end to end. Upload a PDF or text file and
the platform automatically summarizes it, lets you chat with it to
ask specific questions (with answers grounded in and citing the
actual source text), lets you ask questions across your ENTIRE
document library at once, can run live web research on any topic
and synthesize a cited answer, and can generate a polished,
shareable report combining a document's summary, your chat history,
and fresh research into one markdown document you can export as a
PDF. The whole system was deliberately built to run entirely on free
tiers (LLM inference, web search, hosting, and database all have
zero-cost options) while still being safe to expose publicly.

===================================================================
FEATURES
===================================================================

1. DOCUMENT UPLOAD
   Drag-and-drop or click-to-upload a PDF, TXT, or MD file. Files
   are validated for type and size (15MB max) before processing.

2. AUTOMATIC SUMMARIZATION
   On upload, the document's text is extracted and sent to an LLM
   to generate a concise, accurate summary — shown immediately on
   the document's detail page.

3. CHAT WITH A DOCUMENT (RAG)
   Ask natural-language questions about a specific document. The
   system retrieves the most relevant chunks of that document,
   feeds them to the LLM as grounding context, and returns an
   answer that cites which excerpt(s) it used — so answers are
   traceable back to the source text, not just plausible-sounding
   text.

4. MULTI-TURN CHAT MEMORY
   Follow-up questions ("why was that choice made?", referring to
   something asked two messages ago) work correctly because recent
   conversation history is fed back into the LLM alongside each new
   question.

5. LIBRARY-WIDE CHAT ("ask your whole library")
   A separate chat mode that searches across every uploaded
   document at once instead of just one, so you can ask a question
   whose answer might live in any (or several) of your documents.
   Citations show which specific document each fact came from.

6. AUTONOMOUS RESEARCH AGENT
   Give it a topic and it searches the live web, gathers multiple
   sources, and synthesizes a single coherent answer with inline
   numbered citations linking back to the original pages — instead
   of just returning a list of search results for you to read
   yourself.

7. REPORT GENERATION
   Combine a document's summary, its chat Q&A history, and
   optionally fresh web research on a topic of your choice into one
   polished markdown report, generated by the LLM from that raw
   material.

8. PDF EXPORT
   Generated reports can be exported as a PDF directly from the
   browser (using the native print-to-PDF dialog, styled to show
   only the report content in clean black-on-white) — no PDF
   library or added cost required.

9. ACCESS PASSWORD GATE
   A single shared password (set via an environment variable)
   protects the entire API once deployed publicly, so a stranger
   can't rack up charges against your free LLM/search quota. Fully
   disabled with zero friction during local development.

10. RATE LIMITING
    Per-IP request limits on every expensive endpoint (uploads,
    chat, research, report generation) to protect free-tier API
    quotas from being exhausted by abuse or bugs.

11. DOCUMENT MANAGEMENT
    List all uploaded documents with status (processing / ready /
    failed), view details, and delete documents (which cleanly
    removes their chat history and indexed chunks too).

===================================================================
TECH STACK
===================================================================

--- BACKEND ---

Python 3.12
  The language the entire backend is written in.

FastAPI
  The web framework powering the entire API — handles routing,
  request/response validation, and auto-generated interactive API
  docs (available at /docs on the running server).

Uvicorn
  The ASGI server that actually runs the FastAPI application.

SQLAlchemy 2.0
  The ORM (Object-Relational Mapper) used to define and query the
  database — Documents, chat messages, and document chunks are all
  modeled as SQLAlchemy classes rather than raw SQL.

SQLite / PostgreSQL (via psycopg)
  The database itself. SQLite is used by default for zero-setup
  local development (a single file on disk). PostgreSQL (hosted
  for free on Neon) is used in production because it doesn't
  depend on local disk persistence — important since most free
  hosting tiers wipe local files on restart. Switching between the
  two is a single environment-variable change; no code changes
  needed.

Pydantic / pydantic-settings
  Used for two things: validating and shaping all API request/
  response data (so malformed input is rejected automatically with
  clear errors), and loading/validating all environment-variable
  based configuration (API keys, database URL, etc.) in one place.

pypdf
  Extracts raw text from uploaded PDF files so it can be chunked,
  summarized, and searched.

Groq (Python SDK)
  The default LLM provider used during development — chosen because
  Groq offers a genuinely free, fast inference tier (no credit card
  required), unlike most other LLM providers.

Anthropic (Python SDK)
  The production-grade LLM provider (Claude models) — the codebase
  is written so switching from Groq to Anthropic is a one-line
  environment-variable change (LLM_PROVIDER=anthropic), since both
  providers sit behind the same internal interface.

Tavily (Python SDK)
  Powers the autonomous research agent's live web search. Tavily
  was chosen because it has an ongoing free tier (1,000 searches/
  month, no credit card) specifically designed for LLM-driven
  research use cases.

slowapi
  Provides the in-memory, per-IP rate limiting on expensive
  endpoints — no external service (like Redis) required, which
  keeps the whole stack free-tier friendly.

truststore
  A small but important fix: on networks that intercept HTTPS
  traffic (common on corporate/managed networks), Python's default
  certificate handling fails even though the connection is actually
  safe. truststore makes Python use the operating system's own
  trusted certificate store instead, fixing this without weakening
  security.

python-dotenv
  Loads configuration from a local .env file during development so
  secrets never need to be hardcoded.

--- CUSTOM-BUILT COMPONENTS (not third-party libraries) ---

Pure-Python TF-IDF Vector Store (RAG Engine)
  Rather than using a vector database (like Chroma, Pinecone, or
  Weaviate), Cerebrum implements its own lightweight TF-IDF /
  cosine-similarity search engine in plain Python, storing chunks
  directly in the same relational database as everything else.
  This was a deliberate choice: real vector databases either
  require compiled native dependencies (which failed to install on
  this Windows setup without a C++ compiler) or a separate paid/
  hosted service. The TF-IDF approach is less semantically
  sophisticated than true embeddings, but it is free, has zero
  external dependencies, and works identically whether the
  document collection is small or moderate in size — appropriate
  for this project's current scale.

LLM Provider Abstraction Layer
  A small internal interface that both the Groq and Anthropic
  integrations implement identically, so the rest of the
  application never needs to know or care which LLM provider is
  actually answering a request.

--- FRONTEND ---

Next.js 16 (App Router)
  The React framework the entire frontend is built on — handles
  routing (pages for documents, chat, research), rendering, and
  the production build/deployment pipeline (deployed on Vercel).

React
  The underlying UI library Next.js is built on; all interactive
  components (chat, upload, forms) are React client components.

TypeScript
  Used throughout the frontend for type safety — API response
  shapes, component props, etc. are all statically typed, catching
  mismatches between frontend and backend at build time rather
  than as runtime bugs.

Tailwind CSS v4
  Utility-class based styling for the entire UI — the dark theme,
  layout, and all component styling is built with Tailwind classes
  rather than separate CSS files.

@tailwindcss/typography
  A Tailwind plugin that provides sensible default styling for
  rendered markdown content (headings, lists, code blocks) — used
  to display LLM-generated reports and research summaries cleanly.

react-markdown + remark-gfm
  Renders the markdown text returned by the LLM (reports, research
  synthesis) as properly formatted HTML in the browser, including
  GitHub-flavored features like tables and strikethrough.

lucide-react
  Provides all icons used throughout the interface (upload, chat,
  search, lock, etc.) as lightweight React components.

--- DEVELOPMENT & TESTING TOOLS (not part of the shipped app) ---

Playwright
  Used to drive a real headless browser against the running app to
  verify features actually work end-to-end (upload, chat, report
  generation, PDF export styling, etc.) rather than relying only on
  manual testing or unit tests.

Docker
  Used temporarily during development to spin up a disposable local
  PostgreSQL instance, to prove the database code genuinely works
  against real Postgres (not just SQLite) before deploying.

===================================================================
INFRASTRUCTURE / DEPLOYMENT
===================================================================

Render (Backend Hosting)
  Hosts the FastAPI backend on its free tier. Free instances spin
  down after 15 minutes of inactivity and take 30-60 seconds to
  wake back up on the next request — a known free-tier trade-off,
  not a bug.

Vercel (Frontend Hosting)
  Hosts the Next.js frontend — chosen because it has first-class,
  zero-configuration support for Next.js specifically.

Neon (Database Hosting)
  Provides the free, hosted PostgreSQL database used in production.
  Chosen over Render's own database offering because Neon's free
  tier has no time-limited expiration.

GitHub
  Hosts the source code repository that both Render and Vercel
  deploy directly from — pushing a code change and redeploying is
  just a normal git push.
